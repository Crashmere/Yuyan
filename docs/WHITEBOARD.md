# 通用画板实施建议

状态：规划建议，2026-10-07。已核对现有代码、文档和候选引擎的官方资料，尚未实现或完成原型验证。本文细化 [DESIGN 第 25 节](DESIGN.md#25-待讨论事项)，不表示平台已经支持通用画板。

## 1. 目标与建议

目标是把技术资料中的框、文字、箭头、树和关系图保存为可编辑图形，兼顾阅读质量、空间占用与后续定制。这里的“开发自由度”包括自主托管、可控的存储与导出、程序化生成、界面和图形模板定制；不预设第一版需要任意业务组件。

建议先验证 **Excalidraw 嵌入式编辑器 + Yuyan 文档集成 + 数据库图形模板**。采用规整线条、实色填充和普通字体作为技术图默认样式，手绘样式可选。使用公开 API 和原生元素组合，不维护编辑器内核分支。

若原型证明核心需求是可动态增减字段的表节点、字段级连接端口、约束连接和自动布局，而普通形状组合难以满足，则在接入正式存储前改选 **AntV X6**。不同时引入两个画板引擎，也不承诺不同引擎之间无损转换。

节省空间是需要测量的结果：源场景、预览、位图依赖及历史都计入成本。不能用 JSON 的 gzip 大小与 PNG 文件大小直接比较，也不能把“插入了画板”当成“已经减少位图”。

## 2. 现有能力与需求分工

当前正文为 Tiptap JSON，前端 Vue，后端 Go + SQLite。`imageBoard` 的子节点只能是 `image`，用于图片布局和裁切，不保存可编辑的文字、几何形状或连线。Mermaid 已提供源码式流程图。新增通用画板应为独立 `drawing` 块，保留两种已有格式的含义。

| 内容 | 首选表达 | 原因 |
| --- | --- | --- |
| 说明、SQL、规则表格 | 原生段落、代码块、表格 | 可检索、复制和窄屏排版，不必进入画板 |
| 自动布局的流程、时序、简单关系图 | Mermaid | 文本源小、适合程序生成和版本比较 |
| 需要指定空间布局的索引页、B+ 树、扫描过程、架构示意 | 通用画板 | 元素和连线可移动，保留空间关系 |
| 软件界面、照片、复杂真实执行结果 | 图片 | 画板重绘成本高，且可能降低真实性 |

第一版画板包含矩形、椭圆、菱形、文本、直线与折线箭头、端点绑定、自由画笔、颜色、对齐、分布、组合、层级、锁定、复制、撤销、缩放和平移。绑定连线需随目标移动，不能仅画成位置固定的线段。

数据库模板优先用引擎已有元素组成：数据页、记录行、索引键、树节点、扫描路径、事务时间线。图形中的数字、字段名与标签仍为文字元素。组合模板不是有独立渲染逻辑的业务节点，不承诺自动推导数据库结构。

首版以文档内画板为中心，不扩展为独立白板知识库、多人协作、评论系统或演示平台。照片和必要截图可放进画板，但仍计为位图资源。

## 3. 引擎取舍

| 方案 | 可直接使用的能力 | 定制与接入成本 | 许可与判断 |
| --- | --- | --- | --- |
| **Excalidraw** | 较完整的自由画板、图形、连线、文本、素材库、导入导出 | React 组件；在 Vue 弹窗中建立独立挂载点。可定制菜单、样式、程序化元素和组合模板；任意新元素类型并非稳定插件契约 | MIT；当前首选，平衡现成能力和维护量 |
| **AntV X6** | 图编辑引擎、连接端口、路由、选择和对齐等扩展 | 可用 SVG/HTML/Vue 定义节点；需自行建设属性面板、工具栏、图形库及更多完整编辑体验 | MIT；业务节点和结构化技术图优先时更合适 |
| **draw.io** | 成熟的流程图、架构图、ER 等图库和编辑器 | 可配置及扩展图形库；通常通过嵌入协议集成，深改界面和交互需承担更大维护面 | 源码 Apache-2.0；功能覆盖优先的备选，若采用应验证自托管构建，不依赖公共编辑站 |
| **tldraw** | 成熟的无限画布，较强的自定义形状与工具机制 | React SDK；适合围绕画布构建自有应用 | 自有许可，生产使用需适用授权；非商业项目可申请 Hobby 许可，但需获批且保留水印，不按 MIT 或个人使用自动免费规划 |
| **Konva/Fabric 等底层绘图库** | 图形绘制、命中检测、变换等基础设施 | 编辑器行为、连线、文本编辑、导出和历史仍需大量自研 | 即便基础库许可合适，本次也不建议从底层建设整套编辑器 |

Excalidraw 的 `customData` 可以附加元信息，但不等于可注册任意 Vue 组件或自定义渲染器。适配层隔离 UI 生命周期、场景加载、导出和素材处理；场景仍采用引擎原生格式，不额外发明一套“通用图形格式”来限制能力。

## 4. 用户体验与前端接入

- 插入菜单增加“画板”，支持空白、模板和导入 `.excalidraw`。普通图片不会自动变成可编辑图形。
- 正文中显示静态预览，保持固有比例，默认居中，桌面显示宽度一般不超过 800 px，窄屏缩至容器宽度；显示大小与画布内容范围分别控制。
- 通过明确的编辑操作打开大尺寸弹窗，窄屏使用全屏。阅读页可先放大预览；只有进入编辑时加载 React、Excalidraw 及相关资源。普通阅读不加载画板运行时。
- Vue 管理弹窗与文档交互，React 只管理弹窗内部挂载点；关闭时卸载实例和监听。样式限定作用范围，库的浮层和快捷键要实测，避免影响正文工具栏。
- 弹窗内由画板引擎管理撤销；“应用”把整张图作为一次文档事务提交，正文撤销可退回应用前。取消不改变文档。外层退出编辑时，先处理尚未应用的画板草稿，再执行现有文档保存流程。
- 草稿按文档、节点和基准 revision 保存于本机，恢复时检查基准。应用时检查目标节点仍存在且来源未改变；异步导出结果只对应启动时冻结的场景，不能覆盖之后的修改。
- 不把滚动、选中、鼠标移动或每次拖动写成文档修订；仅持久化元素、必要场景设置与有效资源引用。发布时剔除删除元素及无用文件，编辑会话内的撤销仍保留。
- 普通 Tab / Shift+Tab、无焦点装饰、IME 和正文快捷键遵守现有项目约定。弹窗内的撤销与 Esc 先作用于画板；不能触发正文的双 Esc 保存退出。

推荐第一版预览保留明确的画布背景色，在深色阅读页使用中性的容器背景；不直接反转图片颜色或为每张图保存两份预览。中文和长英文标签在编辑、预览与导出中必须保持可读、无裁切。

## 5. 持久化与媒体生命周期

### 5.1 推荐结构

采用内容寻址、不可覆盖的**画板包**，复用 `assets` 存储和 `.bin` 文件。正文中的 `drawing` 只保存包引用、展示宽度、对齐、说明及经校验的派生检索文字，避免整段场景反复复制到每次正文修订中。

画板包包含：

1. Yuyan 包格式版本、引擎名称与保存时的引擎版本。
2. 引擎原生场景：元素及必要的画布设置；不包含选择状态、光标、协作者、编辑历史等临时状态。
3. 引擎文件 ID 到 Yuyan 图片素材 ID 的映射；持久化场景不嵌入图片 Base64。
4. 同一场景生成的一份静态预览、预览类型、边界和场景摘要哈希。

源场景是可编辑内容的唯一依据。预览、边界和检索文字是派生数据，必须随一次发布更新；修改说明或显示大小无需重新保存图形包。同一包可被多个文档或模板引用，编辑其中一处会产生新包并只替换该处引用。

建议新增 `POST /api/drawings` 校验并发布完整包，`GET /drawings/{id}/preview` 提供受认证的静态预览；原始包下载复用附件路径。名称和协议在原型后固定。不能仅把包当普通附件上传，就绕过格式、依赖与预览校验。

前端从冻结的场景生成预览再提交，服务端验证格式、资源归属、哈希和派生文字。哈希只能防止客户端混用场景和旧预览，不能证明两者视觉一致；浏览器预览对照仍是验收项，不引入服务器 Node 或浏览器渲染进程。

### 5.2 预览及体积

- 纯矢量图优先 SVG，保留文字元素；关闭 SVG 中嵌入整份可编辑场景，避免源数据重复。规整线条也减少粗糙笔触产生的多条路径。
- SVG 字体策略是原型的重点：逐图内嵌字体或把所有中文转路径可能抵消节省收益。优先验证普通字体和稳定的系统回退。`<img>` 内 SVG 不会继承页面字体，也不能假设其中的外部字体或图片一定能加载。
- 含位图的图形可使用一份适当分辨率的 WebP/PNG 预览，编辑源仍引用原素材；将预览新增字节计入收益，不另外保存整套多尺寸缩略图。
- 下载独立 `.excalidraw` 文件时，按格式需要临时打包图片；下载 SVG/PNG 时临时生成可移植文件。导出文件中的必要内嵌与服务端长期存储区分计算。
- 静态 SVG 按图片资源返回，不直接作为任意 HTML 注入正文；上传时限制元素、属性和 URL，拒绝脚本、事件、外部资源、DTD/实体和不支持的主动内容。导入的网页嵌入节点也不作为首版能力开放。
- 引擎、字体和必要资源在本机构建并随应用发布，显式配置 Excalidraw 资源路径，不依赖默认字体 CDN。

### 5.3 引用、历史与回收

当前 `mediaReferences` 主要识别节点属性中的直接字符串媒体路径，不会自动理解画板包内的素材映射。必须新增专门的画板引用解析：扫描正文、回收站、历史、模板和片段时，把包及其全部图片依赖纳入现有引用保护。

包只允许引用现有图片素材，不允许引用另一个画板包，避免循环依赖。发布包时检查所有依赖，并与宽限期重置协调；未应用的上传包和依赖在宽限期内也要一致保留。保存文档时再次验证包与依赖可用，不能写入悬空引用。

沿用现有历史保留、连续一小时无引用后回收、备份目录锁与原子发布。回收遇到无法解析的包应停止相关删除并报告错误。已有备份中的硬链接仍会占用空间；替换正文后旧图也可能被历史、模板或其他文档引用，因此实际磁盘释放会延迟。

复用目录和表不代表备份链路自动兼容。需要验证包、图片依赖、历史与模板均进入一致性备份并可恢复；核对现有 v2 清单是否足以描述新增素材，只有需要改变清单契约时才升级格式。

## 6. 文档生态与开发入口

| 接入位置 | 需要闭合的行为 |
| --- | --- |
| `web/src/schema/drawing.ts`（新增）、`schema/extensions.ts` | 节点、属性、包版本及结构校验；未知格式不能静默丢弃 |
| `web/src/drawing/`（新增）、`editor/commands.ts`、节点视图 | 懒加载适配、模板、素材转换、编辑弹窗和单次应用事务；自行管理的视图沿用 `managedNodeView` 约束 |
| `internal/doc/doc.go`、`changes.go` | 节点白名单、容器合法性、检索文字、字符统计与画板修改摘要 |
| `internal/render/`、`web/src/app/content/` | Go 输出轻量预览，按需放大；画板内文字可检索并定位到所属画板 |
| `internal/server/`、`internal/store/asset_references.go`、回收与备份 | 包上传/预览、依赖检查、全部引用根保护、恢复验证 |
| `schema/markdown.ts`、`shared/export.ts`、导入导出工具 | 普通 Markdown 有可阅读的图片回退；Yuyan 导出包保留图形包、依赖和关联元数据，重导可继续编辑 |
| 模板、片段与复制粘贴 | 同应用复制保留包引用；修改按值分离。跨实例导入重新上传包和依赖、重写 ID，不能沿用别的实例的素材地址 |
| `agent-config/skills/yuyan-doc/` | 读取、校验、素材枚举、局部修改、导出与预览适配；后续增加程序化生成入口 |
| `deploy/portal.json`、项目 docs | 新接口和媒体用途登记，写清旧客户端与程序回退边界 |

外部 Markdown 渲染器不理解可编辑画板，因此预览回退是必要行为；可编辑性依靠随导出包交付的源场景，不声称单个普通 Markdown 文件就能无损表达画板。

为 Agent 暴露标准的“矩形/文字/箭头 + ID/坐标/样式”输入，使用官方 `convertToExcalidrawElements` 等 API 生成完整场景；素材、预览与保存复用同一适配层。不要要求模型填写随机种子、版本号等全部引擎内部字段，也不另写第二套布局或格式校验器。

增加节点预计无需 SQLite 表迁移，但旧程序无法安全编辑含新节点的正文。上线时处理旧标签页刷新与能力检查；遇到未知引擎/包版本可显示已保存预览、允许下载原包并明确禁止破坏性重存。程序回退必须选择理解该格式的版本。

## 7. 实施顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| **P0：验证取舍** | 隔离 Vue 弹窗原型；重建 3–5 张有代表性的矩形网格、绑定连线、树或索引图、中文标签与混合位图 | 元素可编辑、箭头跟随、字体一致；样本覆盖无需内核补丁；测量源包和预览总大小、实际加载分块与手机表现，据此确认或改选引擎 |
| **P1：完整首版** | 新节点、编辑/取消/应用、静态阅读、不可变包、检索、历史、引用回收、导入导出、模板与 CLI 保留支持 | 保存重开、正文和弹窗独立撤销、revision 冲突、网络失败、复制、导出重导、备份恢复均正确；未知格式不丢失；普通阅读不下载编辑器 |
| **P2：技术图生产能力** | 数据库模板、可审阅的 Agent 生成与预览入口 | 合成样本可通过同一 CLI 生成、修改、预览和冲突保护；无需手填引擎内部字段；模板不绑定私人文档 |
| **P3：资料迁移** | 另行安排既有图片的逐图分类、重建与局部替换 | 对照原图核对数字、文字、箭头、连接关系和图例；只替换已审核图，记录真实空间变化 |

P0 是决策点，不能仅证明“画布能打开”。正式接入前必须验证所选版本的绑线、中文输入、SVG 字体、资源路径、Vue/React 生命周期及默认键盘策略；若需要频繁修改 Excalidraw 内部代码，应改选引擎或缩小需求，而不是在原型阶段形成长期分支。

P1 的数据与生命周期能力是首版完成条件，不推迟到大量资料写入之后。验证使用隔离数据和合成文档；桌面与 375×667 阅读/编辑操作分别检查，无需为规划新增永久测试。正式实例仅作只读格式兼容检查。

空间评估分别报告：当前素材去重后的实际文件字节；新场景、单份预览与位图依赖的实际文件字节；历史/备份保留期间新增占用；稳态可释放字节。网络 gzip 传输量单列。部分小图即使更大仍可能有编辑价值，但不能计为节省空间的样本。

旧图重建是独立的内容工作。保留文字/表格/代码的原生形式，画板只承载需要空间关系的部分；自动识别可作为初稿，需人工或 Agent 对照审阅。图片转换为图形不是本次平台接入自动获得的能力，迁移数量与工期应在样本通过后评估。
