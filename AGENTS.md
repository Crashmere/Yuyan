# Yuyan Maintenance Entry Point

This project is for personal use: the current change may be released after it has been verified locally; there is no full-regression gate, and permanent tests are not added or retained by default. For UI changes, check the computer and mobile scenarios actually used. For data migrations, bulk writes or deletions, and backup restoration, first perform targeted verification on an isolated copy.

GitHub backs up source code and configuration only; pushing does not trigger tests or deployment. See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) for local entry points and rollback; shared processes are maintained by server-operations.

Read [docs/README.md](docs/README.md) first, then read the design and verification documents required by the task. Before changing a capability, read the DESIGN section listed in the index below. Write verification and release-check records to [docs/VERIFICATION.md](docs/VERIFICATION.md), not back into DESIGN.

When a Yuyan platform capability is added, changed, or removed, the same task must also update `skills/yuyan-doc/` in the personal skill repository `Crashmere/agent-config`, using personal-skill-management. See [yuyan-doc synchronization maintenance](docs/README.md#yuyan-doc-synchronization-maintenance) for the update scope and verification requirements. All skill scripts, references, and skill-specific verification materials belong in the personal skill repository; the Yuyan repository retains only project code and maintenance conventions.

Unless the user explicitly requests another language, write agent-authored specifications and maintenance documentation, technical plans, operational runbooks, decision records, and handoffs in English. Preserve exact Chinese UI labels, matching literals, quotations, fixtures, and required user-facing content whenever translating them would change their meaning or behavior. This default does not determine the language of conversation, product copy, creative work, or other user-requested deliverables.

## Architecture

- Yuyan (语燕) is a web knowledge base for a single user, modeled on the portions of Yuque's web application that are useful for individual use: knowledge bases and document trees, WYSIWYG editing, and reading pages.
- Go with an embedded Vue + Tiptap frontend + SQLite. Document bodies are stored as Tiptap document JSON with a format version number; Markdown is used only for import and export. Startup must fail if the database is missing; only `init` creates a database.
- The frontend is a single-page application: Go returns `internal/server/templates/shell.html` for every page address, and `internal/server/app.go` preloads first-screen data. A preload key must exactly match the API path requested by the frontend; document-body HTML is still rendered by Go. Frontend code is in `web/src/app` (routing, layout, trees, and pages), `web/src/ui` (shared components), and `web/src/editor` (the editor, loaded on demand).
- See DESIGN 12.3 for the initial script budget: only the reading page loads with the application entry point; other pages load on demand, and the page shell preloads the chunk for the addressed page. Register every new on-demand page in `routeViews` in `internal/server/app.go`, or service startup will fail. Where possible, put only logic that does not depend on Vue in an on-demand feature, such as `web/src/app/versions/compare.ts` for version comparison. After changes, use the build manifest to check the chunks loaded initially. Entry-point code must not statically reference reka-ui or floating-ui: use `ActionMenu`, `ContextActions`, and `confirm`/`prompt` for menus and dialogs. Register other modules that the reading page may use at any time through `shared/deferred.ts`; download them on first use and prefetch them while idle (DESIGN 26.5).
- On ali, Yuyan is at `/opt/yuyan`; `yuyan.service` listens on 127.0.0.1:18084 and is accessed through the shared Nginx path `/yuyan/`. See [docs/OPERATIONS.md](docs/OPERATIONS.md) for installation, release, import and export, backup, and diagnostics.

## General Constraints

- Extend document formats only when the user requests it. Before a UI change, read DESIGN section 12, and optimize only within what Markdown can express. On export, write capabilities that Markdown can express as Markdown—for example, put a code block's title and collapsed state in the fence info string. Write other capabilities as HTML and read them back on import, minimizing information loss (`web/src/schema/markdown.ts`).
- When changing the document-body format, update the editor node views, Go static rendering, HTML/Markdown import and export, search, and history summaries together. New nodes and attributes are stored in the document-body JSON and do not themselves require a database migration, but once they are used, the program cannot be directly rolled back to a version that does not recognize them.
- After changing format definitions, `editor/tables.ts`, or other editor configuration, run `roundtrip` (read-only) against the production instance to confirm that existing documents are unaffected. Perform read-only verification only against the production instance.
- Node views for code blocks and image boards that render their own child content must go through `editor/managedNodeView.ts` and return `contentDOM=null` to ProseMirror. By default, the Vue renderer creates a detached content container for non-leaf nodes; when a dialog's accessibility-attribute changes trigger ancestor reparsing, that container is read as empty. These views may write the document body only through transactions. A synthetic document containing code blocks and boards should cover opening, canceling, and applying a dialog, plus saving and reopening.
- Document writes use revision checks for conflicts and must not overwrite silently. Images are content-addressed and immutable. Upload placeholders are decorations and are not written into the document.
- Put button hints in `data-tip`, displayed centrally by `web/src/ui/tooltip.ts`; do not use `title` or a component-library Tooltip for button hints.
- The public site currently uses HTTPS and ServerPortal's unified device authentication. Shared Nginx validates every public page and API. The application must retain its own origin checks on write endpoints.
- Tests use isolated `.local` data. The repository contains synthetic examples only; do not commit real notes. Local zsh lazily loads goenv; if `make` cannot find `go`, prefix the command with `PATH="$HOME/.goenv/shims:$PATH"`.
- An import target must be an empty instance. Rehearse import and export with `--dry` first. After import, run `roundtrip` to confirm that the editor accepts every document unchanged. To try the UI locally, use `seed` to write synthetic data to an empty instance. See docs/OPERATIONS.md for commands and overrides.
- Do not install Node on the server: build the frontend locally and embed it in the program. Before deployment, read server-operations and explicitly read `ssh ali 'cat /opt/AGENTS.md'`. The authorization table in server-operations SKILL.md is the sole authority on what may be done directly and what requires confirmation first.
- The repository is public. Do not commit databases, images, backups, credentials, or the server's public address.

## Capability Index

The parenthesized numbers are DESIGN sections to read before making changes. This index lists only code locations and constraints that must be preserved.

- **Code blocks** (16, 21): titles and collapsed state are defined by `web/src/schema/codeBlock.ts` and shared by the editor, static rendering, and Markdown; the Go side is in `internal/render/render.go`. CodeMirror 6 is in `web/src/code`; `web/src/editor/codeNodeView.ts` and `views/CodeBlockView.vue` connect code changes, selections, and undo to ProseMirror. They do not save document content separately or maintain a second undo history. JetBrains keybindings and help share `web/src/code/keymap.ts`; indentation is fixed at 4 spaces. Formatting runs in the on-demand `format.worker.ts`; asynchronous results verify the source version and language, and separate the document undo history before and after the operation. The reading page retains static HTML and loads syntax folding and the enlarged view on demand. The color scheme is One Dark Pro: the reading page is generated by `internal/render/highlight.go`, while the editor uses CodeMirror One Dark and `web/src/code/style.css`; compare one side whenever changing the other.
- **Alignment** (19): `web/src/schema/alignment.ts`; supports only images, paragraphs, and tables. A cell's `cellAlign` independently overrides the column alignment `align`; whole-table placement is `blockAlign`, while wide-table positioning is still handled by `web/src/shared/tableFrame.ts`. Export alignment as HTML so it is preserved.
- **Image shadows, cropping, and composition** (19, 19.2–19.3): the shadow border is the optional `image.shadow` (`web/src/schema/imageStyle.ts`). Geometry is defined in `schema/imageGeometry.ts`; `imageBoard` contains real image nodes, and the originals remain immutable. Resizing the board and scaling the whole composition are separate operations.
- **Colors, image captions, and table structure** (23.1–23.4): `schema/colors.ts` and `internal/doc/colors.go` share the rules for solid colors, light/dark semantic colors, and fixed text gradients. `textColor` is the text mark, text background uses `highlight.color`, and `backgroundColor` is a cell attribute; the default highlight still exports as `==文字==`. Text color renders inside highlights and links; `markdown.ts` centrally handles the static renderer's reverse mark order. Image captions use `image.caption` and `schema/imageCaption.ts`, independently of alt/title. Tables retain actual header cells and rowspan/colspan structure and do not force the first row to be a header. Export containers containing these formats wholly as HTML and read them back.
- **Format painter** (23.5): `editor/formatPainter.ts` manages temporary sampling and one-shot/continuous modes, using the actual selection range from `selectionContent.ts`. It copies only visual text marks and paragraph styles, preserves target links, images, and code content, and makes each application separately undoable. The top-bar format painter and clear-format controls share the icon in `FormatIcon.vue`.
- **Foldable blocks and highlight blocks** (23.6): formats and the fixed palette are in `schema/blockContainers.ts`, foldable node views and keyboard behavior are in `editor/blockContainers.ts`, and the highlight palette is in `HighlightBlockToolbar.vue`. A foldable view mounts its real `contentDOM`, managed by ProseMirror, and does not use managedNodeView. Move the caret out of body content before collapsing; expand the block when navigating to hidden content or a search match.
- **Columns** (23.7): `schema/columns.ts` defines `columns(widths)` and `column`; `editor/columns.ts` uses a real contentDOM to manage content, with drag handles outside it. Reducing the column count or removing columns must preserve every block in column order. Column widths are proportional weights, and columns display vertically on phones. Maintain structure validation together with the format.
- **Attachments and asset garbage collection** (23.8): the block node is `attachment`, with `schema/attachment.ts`; upload/download is in `internal/server/attachments.go`, preview and archive-directory handling are in `attachment_preview.go` and `attachment_archive.go`, and the reading card is in `app/content/attachmentPreview.ts`. Reuse the `assets` table and directory; non-images use `.bin`, files are published atomically and are immutable. The card name is independent of the stored object, and HTML export preserves portable download links. Attachments have no upload-size limit: PutAttachment accepts an io.Reader, writes to a temporary file in the data directory while hashing, and only the attachment proxy disables size checks and request-body buffering; receiving uses an idle timeout. Image endpoints remain limited to 25 MiB. Unreferenced images and attachments are collected after one continuous hour; references include document bodies (including the trash), history, templates/snippets, and media links. Referencing or uploading again resets the timer; state is stored under `meta.asset_gc:*`. Backup and upload publication share a cross-process lock for the assets directory, while cleanup holds the exclusive lock. First commit deletion of the asset record and its retry marker, then delete the file. Temporary files being uploaded hold the lock; abandoned files are removed after one hour. Diagnose with `gc --dry-run`; old backup programs must not run concurrently with the new collector. Downloads always force attachment disposition. Preview-content endpoints allow only content-identified raster images, PDFs, audio, and video; HTML/SVG displays as source, and archives are not extracted to disk. PDF.js fonts, CMaps, and decoding resources are bundled by Vite with the program. Manifest version 2 backs up images and attachments, while restore remains compatible with version 1. Export packages include the real files; do not treat a Markdown attachment from an export as a note. Update the portal declaration with any change.
- **Links, templates, and snippets** (24): links reuse `/docs/<id>#<slug>` and the anchors produced by reading-page rendering; `internal/server/links.go` derives relationships from live document bodies. Templates are stored in `meta` under `template:<id>`, with an independent revision and the existing JSON format; `editor/templates.ts` closes the selection structure and inserts it in one transaction. Native backup includes templates and images; deleting the source document does not collect resources referenced by templates.
- **Reading-page enhancements** (6.2, 15): behaviors added by the frontend to the Go-rendered body are centralized in `web/src/app/content`: `enhance.ts` (code, tables, formulas, diagrams, and image placeholders; the wide-table frame is in `web/src/shared/tableFrame.ts` and is also used by the editor), `folds.ts` (heading-based folding, expanded with `reveal()`), and `matches.ts` (search highlighting). Call `reveal()` before scrolling to a position in the document body, or the target may be inside a folded section.
- **Segmented reading for very long documents** (26.2): `internal/server/segments.go` divides a fully rendered result (`render.Result.Blocks`) only between top-level blocks and saves it with the render cache. Concatenating all segments must be byte-for-byte identical to the complete HTML. `/view` without `segments=1` still returns the complete document for yuyan-doc. Frontend placeholders are in entry-loaded `app/content/placeholders.ts`; loading is in on-demand `segments.ts`. Navigate through `DocContent` methods `show(id)`, `ensureBlock(i)`, and `loadAll()`. Put new document-body enhancements in `enhance()`; in segmented mode, run them in the staging area inside the placeholder block. Features that traverse the complete document body must skip `.yy-segment`.
- **Very large document edit warning** (26.6): edit load (node count + character count ÷ 100) and the threshold `store.HeavyEditLoad` are in `internal/store/doc_counts.go`; the character-count cache is calculated per revision, and the directory tree marks documents with `heavy`. Every way to enter editing goes through the same guard in `router.ts`; `app.go` redirects a directly opened edit address to the reading page with `?edit=1`. Every new edit entry point must use the router and must not bypass the guard. After editor performance changes, recalibrate the threshold using the method in DESIGN 26.6.
- **Search and slash menu** (13.1, 14, 12.6, 26.4): the server generates pinyin with the go-pinyin dictionary in `internal/server/pinyin.go` (returned with `/api/titles` and `/api/books`, including polyphonic characters); frontend `web/src/shared/searchMatch.ts` only performs matching. Do not add another pinyin dictionary to the frontend or infer pronunciations from sorting rules. Full-text search scans lowercase full text in service-process memory (`store/search_index.go`) and rereads only documents changed according to `revision/created_at`. A new document-body write path must advance the revision or insert a new row, or asset references, character counts, and the search index will all become stale. The slash insertion menu shares the matcher through `editor/insertSearch.ts`; maintain fixed items' per-character pinyin, English keywords, and Markdown aliases in `editor/commands.ts`. An empty query still shows recently used items.
- **Editor UI and outline** (12.6, 17): `EditorPane.vue` provides the editor instance and UI callbacks to toolbars, overlays, and node views through `context.ts`. After table changes, `tables.ts` centralizes column widths and default column alignment while preserving headers and merged structure. Reading and editing pages share `web/src/app/content/OutlinePanel.vue` (appearance, pinning, and folding) and `outline.ts` (determining the current section).
- **Version history** (13.2): snapshots are retained for 30 days and cleaned daily at 03:00 Beijing time, with no guaranteed minimum retained snapshot; `store/version_retention.go` handles catch-up runs, transactional cleanup, and the history-ID high-water mark. The first save records `“编辑前”` (before editing), and restoring records `“恢复前”` (before restoration) in the same transaction; both are subject to the 30-day limit. When normally leaving the edit page, wait for both the document body and snapshot to complete. After history removes the final reference, an attachment's one-hour timer restarts; the current document body, trash document bodies, and templates continue to protect assets. Diagnose with `history-gc --dry-run`. `internal/doc/changes.go` creates summaries by comparing adjacent snapshots, without an external model or a database migration.
- **Database layout and migration** (26.1): `internal/store/migrate.go` executes layout steps in order; `meta.layout`/`min_layout` are separate from the document format version `meta.schema`. The table-creation constants in `store.go` are shared by `init` and migration, with large fields last. Each step uses one transaction and commits only after foreign-key checks pass. Table rebuilds copy columns by name and must not drop columns. Steps compatible with older programs do not raise `min_layout`, so SQL must name columns explicitly. `Open` (serve/check/restore) migrates; backup uses `OpenAsIs` to preserve the existing layout. During release, the new program migrates in `check` after the backup; first measure the duration of longer-running steps against a copy of the production backup.
- **Document calendar** (27): `web/src/calendar/CalendarPanel.vue` edits independent `calendar` atoms; `schema/calendar.ts` and `internal/doc/calendar.go` define their document format, and `calendar/dates.ts` owns UTC-safe date/window/lane calculations. Keep insertion, pending-draft flush, undo, Go rendering, lazy reading enhancement/cleanup, search/character counts, history, Markdown/HTML preservation, and yuyan-doc synchronized. Periods live only in document JSON and use document revision checks. `calendar/transfer.ts` owns the shared `YYCAL1:` clipboard codec: valid imports apply directly in one undo step; only clipboard/parse failures open correction prompts. Preserve complete year/month boundaries, stable overlap lanes, and local pointer drafts until application. Touch retains the explicit editor path. Layout 4 removes the retired standalone table and raises `min_layout` to 4; old programs cannot reopen it. Do not restore standalone routes or storage.
- **Knowledge-base groups** (12.5): use the existing `meta.book_groups`; GET/PUT `/api/book-groups` uses revision conflict checks. Group display shares `bookSections`; permanently deleting a knowledge base also cleans up its membership.
- **Image display variants** (7, 26.3): rules are in `internal/variants/generate.go` (quality checks in `quality.go`, resizing in `resize.go`), with the derived directory and background worker in `cache.go`. The size-table query and `/assets/<id>-<file>` are in `internal/server/images.go`; the frontend uses `displayVersions` from `shared/images.ts`. Originals do not change; export, backup, original-image viewing, and yuyan-doc use originals only. `data/derived/images` may be deleted and is not backed up; increment `variants.Version` when changing the rules. Do not switch scaling back to `draw.CatmullRom.Scale`: it caches a float64 buffer at the full image height for the new width, while the service has only 384 MiB. The size table's third item is the list of version files, and the fourth is the list for 2×-and-higher screens (it may include files from the third item; the server selects each tier, while the frontend selects only by `min-resolution: 2dppx`, not by filename). The manifest's `for` identifies versions that belong to only one tier set. When original dimensions are needed, query the size table instead of reading `naturalWidth`. The editor image node's `toDOM` includes `loading="lazy"`, so the initial render before the node view mounts does not download the original.

## Portal Resource Synchronization

- The portal display name uses the English brand name `Yuyan`, without Chinese appended; the name is maintained in deploy/portal.json.

- When changing the site icon or authentication, also check the iPhone apple-touch-icon, post-build paths, and anonymous GET/HEAD. Only explicit exceptions for brand icons and the public manifest are allowed; pages, APIs, and user media must still require authentication. See server-operations common-issues for unified troubleshooting and acceptance; current-state is authoritative for what is actually enabled.

- This project's `deploy/portal.json` is the maintenance source for the ServerPortal resource declaration. It records directory purposes, databases, the runtime user, port, unit, access path, APIs, and backup types. When adding, migrating, or removing a data root, endpoint, or runtime material, update the declaration, the corresponding docs, and the shared application inventory together.
- The declaration is deployed at `/opt/yuyan/config/portal.json` and managed by root. Local release reuses the server-operations validator: preflight before release, then automatically synchronize through restricted SSH and verify the portal-loaded hash afterward. `registry.d/yuyan.json` registers links automatically; updates do not require a portal restart.
- Shared Nginx and the portal provide unified authentication; this project does not store a separate device allowlist. Local calls and release health checks retain the shared exceptions. Device authentication is enabled in production; after changes, synchronize server-operations current-state.
- The portal's read-only display does not replace this project's native consistent backups. When a backup format or media lifecycle changes, perform isolated verification of the affected backup and restore contracts. Real business data, credentials, and backups must still never enter Git.

Local release automatically preflights and synchronizes the committed `deploy/portal.json`. To update only the declaration, run `make portal`, preserving the business program version.

By default, the web application blocks Tab / Shift+Tab control traversal and removes focus highlighting; retain only exceptions explicitly requested by the user. Follow the [server-operations web keyboard and focus conventions](https://github.com/Crashmere/agent-config/blob/main/skills/server-operations/references/conventions.md#网页键盘与焦点) for maintenance and verification.

An editable whiteboard is an independent atomic `drawing` block that uses a pinned Excalidraw engine, immutable packages, and derived previews. See [docs/WHITEBOARD.md](docs/WHITEBOARD.md) for all format/API, dependency-protection, unknown-version, and rollback constraints. Asset dependencies must be expanded in publication transactions and GC; synchronize new whiteboard capabilities to yuyan-doc. Do not describe embedding an image in a whiteboard as vectorization or claim space savings without measurement.
